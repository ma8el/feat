Feat runs on macOS and Linux. Desktop notifications are macOS-only; the dashboard's attention badges work everywhere.

## Prerequisites

Feat needs these on the machine:

- **Git** and **tmux**. Feat drives Git for every branch, worktree, and diff, and runs every agent session in tmux.
- **Claude Code, installed and authenticated.** [Claude Code](https://code.claude.com/docs/en/setup) is the agent Feat launches, and nothing runs without it. It has to be where the agent runs: on this machine in host mode, inside the image for a devcontainer.
- **The Docker Compose CLI**, only for a devcontainer or an application runtime.

`feat doctor` checks all of this and says what to do about what it finds.

## Getting the binary

::tabs
  :::tabs-item{label="Homebrew" icon="i-simple-icons-homebrew"}
  On macOS:

  ```sh
  brew tap ma8el/feat
  brew install --cask feat
  ```

  It brings Git and tmux with it, and it is the one route that needs no `xattr`. It is a cask rather than a formula, so it is macOS only: Homebrew on Linux does not install casks.
  :::

  :::tabs-item{label="Release archive" icon="i-lucide-archive"}
  The [releases page](https://github.com/ma8el/feat/releases) has one `tar.gz` per platform and architecture: `darwin_arm64` for Apple Silicon, `darwin_amd64` for an Intel Mac, `linux_arm64`, and `linux_amd64`.

  ```sh
  curl -LO https://github.com/ma8el/feat/releases/download/v0.2.0/feat_0.2.0_darwin_arm64.tar.gz
  tar xzf feat_0.2.0_darwin_arm64.tar.gz
  mv feat_0.2.0_darwin_arm64/feat /usr/local/bin/   # or anywhere on your PATH
  feat version
  ```

  The archives are not notarized. On macOS, an archive downloaded through a browser is quarantined; clear it with `xattr -d com.apple.quarantine feat`.
  :::

  :::tabs-item{label="go install" icon="i-simple-icons-go"}
  With the Go toolchain that [`go.mod`](https://github.com/ma8el/feat/blob/main/go.mod) pins:

  ```sh
  go install github.com/ma8el/feat/cmd/feat@latest
  ```
  :::

  :::tabs-item{label="From source" icon="i-lucide-code"}
  ```sh
  git clone https://github.com/ma8el/feat.git
  cd feat
  make build   # ./bin/feat
  ```
  :::
::

## Your first project

A **project** is the set of repositories a task may work in, together with how its agent runs and how its work is checked. It is one YAML file you write once; `myproject` below is its identifier. Most projects are one repository, and a task may span several.

In one of your project's checkouts:

```sh
feat doctor          # changes nothing, needs no daemon: run it first
feat project init    # answer the questions; it writes a validated configuration
feat daemon start
feat project add myproject
feat implement       # or `feat` for the dashboard
```

`feat project init` prints those last commands itself, and offers to run the checks and the registration for you. [Configuring a project](https://github.com/ma8el/feat#configuring-a-project) covers the same ground at length.

For more help with a project's configuration:

- `feat skill install` writes a setup skill into your own Claude Code session. It helps you edit a project that already exists or write one from scratch.
- `feat project schema` and `feat project example` print the schema and a commented example, for writing the file by hand.

## Shell completion

Completion works in bash, zsh, and fish. It completes commands, flags, and project names, but not task identifiers. Bash needs the `bash-completion` package. Add this to `~/.bashrc`:

```sh
source <(feat completion bash)
```

For the others, see `feat completion zsh --help` or `feat completion fish --help`.
